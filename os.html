What it actually is

The Vault is a folder on your computer that Claude Code reads. Inside it: the playbooks for every deliverable an agency sells, the personas that run them, your clients' real context, and the quality rules that stop bad work from shipping. You talk to it normally — it loads the right role, the right playbook, and the right client, then produces the work.

The difference from plain ChatGPT: a chat has no memory of your business, no process, and no standard. The Vault has all three, permanently.
Get started

Install in 10 minutes

Mac. You need a GitHub account we've granted access to, then two free tools and one line.

Terminal
# 1 · install Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2 · turn Homebrew on (shows nothing — that's normal)
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

# 3 · install the two tools
brew install git gh

# 4 · log into GitHub FIRST (this order matters)
gh auth login

# 5 · install the Vault
curl -fsSL https://agentic-marketers.vercel.app/update | bash

Then open the AgenticMarketersVault folder in Claude Code and type /mybusiness to teach it about you.

Windows: skip Homebrew. Install with winget install --id Git.Git -e and winget install --id GitHub.cli -e, then run steps 4–5 inside Git Bash (not PowerShell).

Systems

D100 — the client-getting machine

The flagship system. It finds your dream clients, builds each one a finished funnel for free, publishes it as a proposal page, and puts them into an email sequence. You show up as the person who already did the work.

Setup: 6 questions

  • 1Which engine? VSL, Challenge Funnel, or Webinar — one or more. Toggle any on/off later from the dashboard.
  • 2Niches — who to target. Only asked for the engines you turned on.
  • 3Keys — Vercel, Instantly, plus Apollo and/or Apify. Each one is tested live before it's saved.
  • 4Daily volume — 25 / 50 / 100 / 250 new prospect builds a day.
  • 5Your details + proof — booking link, contact, and results you can honestly claim.
  • 6Your headline — the copywriter drafts your proposal hook from that proof.

Then, per prospect

  • →Qualify — poor-fit leads are skipped, never built.
  • →Research — their real offer, audience, proof and brand colours.
  • →Angle — a sharp hook framed to the market they actually serve.
  • →Build — the funnel and assets for their track.
  • →Proposal — a live page with your identity, their research, real proof only.
  • →Outreach — a 3-email sequence, sent and tracked automatically.

The dashboard

A private web dashboard deploys during setup: Leads (your pipeline), Build (run a batch of 10–250 with a live progress bar), Daily Volume, D100 Types (toggle engines), Scheduler, and API Limits (usage with upgrade alerts). Every send, open and reply marks itself on the lead automatically.

How it thinks

Routing

You don't pick the skill. You describe the job and the Vault routes it, in this order:

  • 1Slash command — if you typed one, it wins.
  • 2Your overrides — anything in Custom/ beats the defaults.
  • 3Phrase match — the trigger map maps what you said to a role.
  • 4Multi-step request — chains several roles into a pipeline.
  • 5Fallback — the skill resolver searches the whole library.
Say "write me an email for Acme" and it loads the copywriter, Acme's voice and offer, the email playbook, and the quality gates — without you naming any of them.
How it thinks

Rules & quality gates

This is what separates the Vault from a chat window. The rules aren't suggestions in a prompt — they're code that blocks bad output before you see it.

The hard rules

  • ✕Never invent proof. No fabricated stats, testimonials, case studies or guarantees. If there's no real number, the copy ships without one.
  • ✕No em dashes, no AI tells. A banned-phrase list kills "in today's landscape", "game-changer", "leverage", "seamless" and dozens more.
  • ✕No AI cadence. Three punchy sentences then a long one, stacked rhetorical questions, repeated "it's not X, it's Y" — all flagged.
  • ✓Client isolation is absolute. One deliverable loads exactly one client's data. Never borrows from another.
  • ✓Golden rules per client. Each client's non-negotiables (never say X, always say Y) hard-block output that breaks them.

The three-test

Every headline and claim must pass all three, or it gets cut: Can the reader picture it? · Could it be proven false? (specific, not vague) · Could nobody else say it? (ownable, not a category cliché).

Where the gates fire

MomentWhat runs
On writeGolden rules check every file as it's saved
Before you see itThe deliverable gate scans 17 output types for specificity, proof and structure
Before it sendsThe send gate checks anything going outbound
Before generatingContext readiness blocks generic output when a client's context is empty
On creativeThe creative gate blocks design work with no concepts or a failed critique
Fail-closed: if a gate can't reach a verdict, the work does not ship. Silence is never treated as a pass.

Every deliverable belongs to exactly one business context, and the Vault resolves it before writing a word.

WorkspaceWho it's for

MyBusinessYour own business — treated exactly like a client
Projects/{name}A launch or campaign that isn't either

Each holds the same things: the business profile, the offer/copy/research foundations, the voice samples and the golden rules. Name a client and it loads theirs. Name none and it uses yours.

How it thinks

Memory

The Vault gets better the more you use it. Correct it once and the correction sticks.

  • →Corrections are captured automatically. When you say "no, that's wrong," it's logged and structured.
  • →Phrase-level corrections become hard rules. Tell it never to say something and it becomes a blocking gate, not a note.
  • →Session breadcrumbs mean the next session knows what the last one did.
